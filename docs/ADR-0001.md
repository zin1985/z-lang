# ADR-0001: Independent Z core, hybrid execution

- **Status**: Proposed / principle-level accepted for initial draft
- **Date**: 2026-10-15
- **Decision owner**: Project maintainers

## Context
Z aims to be AI-first and human-verifiable. A fully bespoke compiler/runtime offers freedom but makes adoption, integration, performance and maintenance difficult. Merely adding annotations to an existing language constrains semantics and risks reducing Z to a wrapper.

## Decision
1. Z owns its canonical semantics, typed intermediate representation (ZIR), trust/effect model, evidence schema, and human-oriented Inspector.
2. Pure calculations are implemented first in a small reference interpreter.
3. Backend interface is defined explicitly. WebAssembly / LLVM / foreign-language adapters may be added when the reference semantics and conformance tests exist.
4. Backends MUST NOT silently broaden effects or weaken intended guarantees.
5. No backend choice alters the meaning of an approved Intent.
6. Everything is versioned: ZIR schema, runtime, checker, evidence and approvals.

## Consequences
- Advantages: architectural independence, smaller MVP, gradual portability.
- Costs: semantic mapping, trust boundaries, cross-backend testing.
- Open: exact language grammar, canonicalization algorithm, verification backend, licensing.

## Alternatives considered
A. Fully bespoke language + runtime immediately: too high an up-front cost.
B. New syntax on top of Python/JavaScript: too much inherited ambiguity and hidden effects.
C. Independent core + replaceable execution (selected).
