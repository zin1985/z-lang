# Z Requirements / 要求仕様一覧
Version: 0.1 (draft) | 2026-10-15

この文書は提案段階の要求ベースラインであり、実装済みを意味しない。

## Terminology and priorities
- **MUST / P0**: Z Coreの成立に必要な基本要求
- **SHOULD / P1**: 初期実用品質で必要
- **FUTURE / P2**: 設計時に拡張余地を確保する
- **Draft**: 未承認の暫定提案。決定状態を追記して管理する。

## Nonfunctional requirements

|---|---|---|---|

| Z-NFR-002 | P0 | AI生成物を未信頼入力として扱う | 不正ノード・未知フィールドを拒否 |
| Z-NFR-003 | P0 | ZIRスキーマと検証規則は公開・バージョン管理 | 仕様差分を参照可能 |
| Z-NFR-004 | P0 | 同一ZIRに対して正規化/ハッシュが安定 | テストベクタで検証 |
| Z-NFR-005 | P1 | 依存関係と再現手順を記録 | 別環境で再実行可能 |
| Z-NFR-006 | P1 | 機密データのログ漏えいを制御 | 秘匿フィールドのテストに合格 |
| Z-NFR-007 | P1 | 検証結果は機械可読・追跡可能 | CIやInspectorに同じ結果を渡せる |
| Z-NFR-008 | P1 | 形式検証が不可能/未対応の領域を明示 | unsupported / unknown を返す |
| Z-NFR-009 | P1 | バックエンドの差分で仕様が変質しない | バックエンド横断の適合テスト |
| Z-NFR-010 | P2 | 大規模グラフの増分解析 | 無関係な領域の再検証を抑制 |

## First milestone acceptance (M0)
- JSONに準じたZIRの最小スキーマを確定し、構文・型検査の成功例/失敗例を揃える。
- 事前/事後条件を持つ副作用なしの関数1つ（割引計算）を宣言・実行できる。
- 誤った実装を与えた時に、少なくとも一つのテストが失敗する。
- 実行できても「証明済み」と誤表示しない。
- AIの仮定や未決事項がInspector上で目立つ形で出力される。

## Open questions (not yet approved)
1. 言語のテキスト構文を定義するか、ZIRのみを正式な原本とするか。
2. 整数、金額、浮動小数点、オーバーフロー、端数処理の厳密な意味。
3. 形式証明とSMT検証の範囲、検証不能時の扱い。
4. ZIRのノードIDとコンテンツハッシュの境界。
5. 人間承認の真正性、取消し、有効期限、責任分界。
6. 外部バックエンド/ライブラリの信頼水準。
7. 公開ライセンスと外部コントリビューション運用。
