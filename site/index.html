01 / WHY Z EXISTS

コードの先にある、
新しい合意の形。

AIにとって便利なのは、大量に書ける言語ではなく、間違いを減らせる言語だ。

「正しそうなコードが動いた」だけで終わらせない。何を望んだのか。何が実装されたのか。何を根拠に正しいと判断できるのか。その3つを、最初から結びつけます。

ONE SYSTEM · THREE INDEPENDENT CONCERNS
02 / THREE PILLARS

言語の中心は、
命令ではなく「意図と根拠」。

Zは、従来の「実装」を唯一の中心に置きません。意図・実装・根拠をそれぞれ独立して管理し、機械が結び付きを検査できることを目指します。

PILLAR / 01◎

Intent 意図

目的、入出力、事前・事後条件、不変条件、権限、未確定事項。AIの推測と人間が承認した要求を区別します。

PILLAR / 02⌘

Implementation 実装

AIが生成する、型付きで機械実行可能な処理。内部表現を原本にし、ソースコードは表示方法の一つにします。

PILLAR / 03✓

Evidence 検証根拠

テスト、静的解析、形式的証明、レビュー結果。何を、どの条件で確認できたのかを区別して保持します。

03 / THE Z CHARTER

設計をぶらさない、7つの原則。

実装方式が変わっても、守るべき基準は変わらない。Zの最初の憲章から。

01
AIファースト、人間が検証可能

AIによる構築と、人間による理解・判断・承認の両立を目指す。

02
要求と実装を混同しない

AIによる仮定を、承認済みの仕様として扱わない。

03
検証は独立した仕組みで

AIの自己申告を証拠とせず、機械的な検証結果を分離する。

04
「分からない」を明示する

未確定・未検証・矛盾・失敗を、成功と混同しない。

05
副作用と権限を可視化する

通信、データ更新、削除、決済などの作用を宣言する。

06
変更を振る舞いで捉える

行単位の差分だけでなく、仕様・影響・リスクの差を示す。

07
独立した核、交換可能な実行系

Zの意味と検証規則は独立し、実行基盤は交換できるようにする。

04 / THE ARCHITECTURE

独立した意味論。
交換可能な実行環境。

独自のZIR（Z Intermediate Representation）を言語の核に据え、検証器と人間向けInspectorを通して実行へ進みます。

01 / AUTHOR

要求 + AI生成

目的、制約、仮定、未決事項を構造化してZIR草案を作成。

02 / VALIDATE

ZIR + Validator

型、契約、副作用、依存関係、証拠を独立に検査。

03 / REVIEW

Z Inspector

人間が理解すべき影響・危険・不明点・根拠を提示。

04 / EXECUTE

実行バックエンド

最小インタプリタから開始し、Wasm / LLVM等へ段階的に拡張。

Independent Core + Hybrid Execution. 最初から万能VMを自作するのではなく、言語の意味と検証の独立性を確保しながら実用性を高めます。

05 / WHAT REVIEW COULD LOOK LIKE

書かれたコードより、
確かめるべきことを。

同じ会員割引機能を、実装・検証根拠・人間用レビューという異なる視点から表示するイメージです。

人間は「何が起こるか」を承認する。

実装が長大になっても、未決事項や副作用、検証状況を中心に確認できることを目指します。

テストに合格したことと、すべての入力で正しいことの数学的証明は別です。Zではその違いを表示します。

08 / QUESTIONS

よくある疑問。

Zはもう動きますか？

まだ動きません。現在はv0.1の設計構想と要求仕様を公開した段階です。最初に、ZIRスキーマ、独立検証器、純粋関数インタプリタを実装します。

プログラマーが不要になる言語ですか？

実装作業の多くをAIへ移し、人間が要求の決定・判断・検証を担える未来を目指しています。ただし専門的な監査や設計・安全性の責任まで消えると主張するものではありません。

テストに通れば正しいと保証されますか？

保証されません。テスト、形式的証明、レビュー、実環境での観測は異なる種類の根拠です。Zはそれらを区別して管理し、保証できない部分を明示することを目指します。

なぜ独自言語にするのですか？

Intent（意図）とEvidence（検証根拠）を、既存言語への後付けの注釈ではなく、言語の第一級要素にするためです。実行系には既存技術を活用し、必要な部分のみ独自に設計します。

同じ名前のZ言語がありますか？

はい。形式手法の分野には既存の仕様記述言語「Z notation」があります。このプロジェクトのZは別の構想です。名称の混同や商標の調査は今後の課題です。

公開されているなら自由に使えますか？

リポジトリは公開されていますが、現時点でライセンスは未決定です。公開は無条件の再利用許諾を意味しません。貢献方針とOSSライセンスは今後定める予定です。
